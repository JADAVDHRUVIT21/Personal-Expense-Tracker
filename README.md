Introduction
Managing personal finances is important for understanding spending habits, keeping financial records organized, and planning budgets. Manual tracking can be time-consuming and makes it difficult to review expenses over time.

Personal Expense Tracker is a web-based application designed to provide a central place for users to manage personal finance information. React powers the user interface, FastAPI handles API requests and application logic, and PostgreSQL stores application data.

The project includes account-related workflows such as registration, login, profile management, password changes, and logout confirmation. It also has database models for users, categories, expenses, and budgets, providing a foundation for tracking spending and planning budgets.
Project Objectives
- Build a user-friendly web application for personal finance management.
- Support account registration and authenticated access.
- Store application information in a relational database.
- Allow users to view and update profile information.
- Support password changes with current-password verification.
- Connect frontend and backend through REST APIs.
- Use database migrations to manage schema changes.
- Keep the architecture maintainable and extendable.

Request Flow
1. The user interacts with the frontend.
2. React sends an HTTP request to the appropriate FastAPI endpoint.
3. FastAPI validates the request and checks authentication where required.
4. SQLAlchemy performs database operations.
5. PostgreSQL stores or retrieves the requested data.
6. FastAPI returns a response to the frontend.
7. React updates the interface and displays feedback.
Research and Design Considerations
Separation of Concerns
The frontend focuses on presentation and user interaction, the backend handles application logic and validation, and PostgreSQL provides persistent storage. This separation makes components easier to maintain and test.
Relational Data
Users, categories, expenses, and budgets are naturally represented as related data entities. PostgreSQL supports relational constraints and transactions to help maintain consistency.
API-First Development
The frontend and backend communicate through HTTP endpoints. FastAPI generates interactive API documentation that assists with development and testing.
Security and Validation
Protected endpoints should validate authentication and authorization on the backend. Frontend validation improves usability but cannot replace server-side validation.
Usability
Responsive layouts, clear field labels, in-page feedback, and confirmation dialogs help users understand actions and avoid accidental operations.

Installation and Setup
Prerequisites
Install the following tools:
- Python 3.13
- Node.js and npm
- PostgreSQL
- Visual Studio Code
- Git (optional, for version control)
1. Clone the Repository
git clone https://github.com/JADAVDHRUVIT21/Personal-Expense-Tracker.git
cd Personal-Expense-Tracker
If the project is already present on your computer, open the existing folder instead.
2. Configure PostgreSQL
Create a PostgreSQL database named:
personal_expense_tracker
Configure backend/.env using the variable names expected by the project's settings. For example, if the settings use DATABASE_URL:
DATABASE_URL=postgresql+psycopg://USERNAME:PASSWORD@localhost:5432/personal_expense_tracker
Replace USERNAME and PASSWORD with your local database credentials. Do not commit actual credentials or secret keys.
3. Create or Activate the Backend Virtual Environment
Open PowerShell in VS Code:
cd D:\Personal-Expense-Tracker\backend
If the venv folder already exists, activate it:
.\venv\Scripts\Activate.ps1
If it does not exist, create it using Python 3.13 and then activate it:
py -3.13 -m venv venv
.\venv\Scripts\Activate.ps1
4. Install Backend Dependencies
If requirements.txt exists:
python -m pip install -r requirements.txt
5. Apply Database Migrations
With the virtual environment activated:
python -m alembic upgrade head
6. Install Frontend Dependencies
Open a second terminal:
cd D:\Personal-Expense-Tracker\frontend
npm install
Running the Project
Start the Backend
In the first terminal:
cd D:\Personal-Expense-Tracker\backend
.\venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --reload
Backend URLs:

Open the local address printed by Vite, commonly http://localhost:5173.

Keep both terminals running while using the application.
How the Application Works
Authentication Workflow
1. The user registers or logs in through the frontend.
2. The backend validates the submitted information.
3. After successful authentication, the frontend receives authentication information.
4. Protected requests send the access token in the Authorization header.
5. The backend validates the token before returning protected data.
Example header:
Authorization: Bearer YOUR_ACCESS_TOKEN
Profile Workflow
1. Open My Profile from the navigation bar.
2. The frontend calls GET /api/v1/auth/me.
3. The backend returns the current user's profile data.
4. Edit the name and select Save Name.
5. The frontend sends PATCH /api/v1/auth/me.
6. The backend saves the new name.
7. The frontend displays a success or error notification.
Password Change Workflow
1. Enter the current password.
2. Enter and confirm the new password.
3. The frontend checks that required fields are present and the new passwords match.
4. The frontend calls POST /api/v1/auth/change-password.
5. The backend verifies the current password.
6. If valid, the backend stores the new password hash.
7. The frontend displays the result.
Logout Workflow
1. Click Logout.
2. A confirmation dialog appears.
3. Select Cancel to close the dialog and remain logged in.
4. Select Yes, Log Out to confirm.
5. The logout logic runs and the application navigates to /login.

Security Considerations
- Store passwords as secure hashes, never as plain text.
- Keep .env files and credentials out of version control.
- Use strong secret keys for token signing.
- Authenticate and authorize protected backend routes.
- Validate data on the backend, even when the frontend also validates it.
- Ensure users can access only records they are authorized to view.
- Avoid logging passwords, tokens, or sensitive financial details.
- Use HTTPS and production-appropriate authentication handling when deployed.
- Use database credentials with only the permissions the application needs.
